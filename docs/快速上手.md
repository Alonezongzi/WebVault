# WebVault 快速上手

WebVault（网页金库）把一个网址变成**一个自包含的 `.html` 文件**——CSS、图片、字体全部内联成 data URI，双击就能打开，断网也能看，可以直接丢 U 盘、发微信。它不生成 `xxx_files` 文件夹，产物永远是单个文件。除了完整快照，它还能抽出正文做干净阅读版，或者干脆不产出页面、只吐结构化 JSON。

---

## 环境要求

| 项目 | 要求 |
|---|---|
| Python | 3.8 及以上 |
| 第三方库 | **不需要**，纯标准库 |
| 可选加速 | `lxml`（解析提速）、`Pillow`（图片压缩）。装了就用，没装照样跑 |
| 网络 | 抓取时要能访问目标站点 |

不需要 `pip install` 任何东西，也不需要建虚拟环境。下载解压，`cd` 到目录就能用。

```
gift/
├── webvault.py        命令行入口（保存 / index / discover / diff）
├── webvault-ui.py     本地网页操作台
├── src/               核心实现
├── tests/             自测套件
├── docs/              文档
└── examples/          示例产物
```

两个入口脚本都会自动把自己所在的目录加进 `sys.path`，所以在哪个目录下敲命令都行。

## 最常用的三条命令

### 1. 存一篇文章（默认 reader 模式）

```bash
python webvault.py https://example.com
```

输出大概是这个形状：

```
 __      __     _  __     __         _ _
 \ \    / /    | | \ \   / /        | | |
  ...
  网页 → 单文件离线副本          v1.0.0

  · 抓取 https://example.com
  · 已抓取 https://example.com（HTTP 200，1.2 KB）
  · 解析并提取正文…
  · 内联资源（图片/CSS/字体）…
  · 资源：抓取 0 / 内联 0 / 跳过 0 / 失败 0；原始 0 B → 内联 0 B；预算 0 B/24.0 MB (0%)
  · 已保存 /当前目录/vault/Example-Domain.html（4.1 KB）

✔ 完成
  标题   Example Domain
  模式   reader
  大小   4.1 KB
  正文   93 字，0 图
  资源   抓取 0 / 内联 0 / 跳过 0 / 失败 0；原始 0 B → 内联 0 B；预算 0 B/24.0 MB (0%)
  耗时   1.2s
  文件   /当前目录/vault/Example-Domain.html
```

文件名由页面标题生成（中文保留，`/ \ : * ? " < > |` 会被替换成 `_`）；标题取不到时退回域名。同名文件不会被覆盖，会自动加 `-1`、`-2` 后缀。

默认输出目录是**当前工作目录下的 `vault/`**，用 `-o` 换：

```bash
python webvault.py https://example.com -o D:\saves
```

### 2. 原样存档一个页面（full 模式）

```bash
python webvault.py news.site.com/article/123 -m full
```

`http://` 可以省，脚本会补 `https://`。

full 模式保留整页结构（导航、侧栏、页脚都在），只把所有外部资源内联进来，再在页面底部加一条来源条，显示抓取时间、原文链接、体积，带一个「隐藏」按钮。

```
✔ 完成
  标题   某篇文章标题
  模式   full
  大小   1.8 MB
  资源   抓取 42 / 内联 38 / 跳过 3 / 失败 1；原始 1.9 MB → 内联 2.5 MB；预算 2.5 MB/24.0 MB (10%)
  耗时   6.4s
  文件   D:\saves\某篇文章标题.html
```

注意「原始 1.9 MB → 内联 2.5 MB」——base64 大约有 1/3 的膨胀，这是单文件方案必须付的代价。末尾那段「预算 2.5 MB/24.0 MB (10%)」是按 base64 之后的体积扣的，所以 `--max-total 24` 就是内联资源占用的上限，产物不会比它大。

### 3. 只要结构化数据（data 模式）

```bash
python webvault.py https://example.com -m data --stdout
```

`--stdout` 不写文件，直接把 JSON 打到终端：

```json
{
  "url": "https://example.com/",
  "final_url": "https://example.com/",
  "requested_url": "https://example.com",
  "captured": "2026-10-17 00:46:39",
  "generator": "WebVault",
  "title": "Example Domain",
  "byline": "",
  "excerpt": "",
  "site_name": "example.com",
  "lang": "zh",
  "text": "This domain is for use in documentation examples ...",
  "html": "<body><p>This domain is for ...</p></body>",
  "word_count": 93,
```

去掉 `--stdout` 就会存成 `.json` 文件。字段含义见[命令行手册](命令行手册.md#data-模式的-json-结构)。

## 启动本地网页操作台

```bash
python webvault-ui.py
```

```
WebVault v1.0.0
  界面   http://127.0.0.1:8770/
  保存    C:\Users\<你>\Desktop\WebVault
  停止   Ctrl+C
```

默认会**自动打开浏览器**，在页面里粘贴网址（一行一个）、选模式、点保存。界面本身零依赖——没有 CDN、没有框架，断网也能打开。

常用参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--port` | 监听端口 | `8770` |
| `--host` | 监听地址 | `127.0.0.1` |
| `--out` | 保存目录 | 桌面下的 `WebVault`（桌面不存在则用用户主目录） |
| `--no-browser` | 不自动开浏览器 | — |

端口被占用时会自动往上试，最多试 12 个端口。界面上有「内联图片 / 内联 CSS / 压缩大图 / 仅同域资源 / 干净排版（丢原站样式）」几个开关，还有 `Ctrl+Enter` 快捷提交。任务列表会持续轮询，显示每个 URL 的体积、耗时、内联统计和失败原因。

几个和命令行不完全一样的地方：

- 「总大小上限 (MB)」和「单资源上限 (MB)」这两个数字框会校验：填成 `abc` 这类非法值会退回默认值（24 / 4），不会报错。超时也一样，服务端把它夹在 5–120 秒之间。
- 「干净排版（丢原站样式）」的语义是**反的**：勾上等于「不保留原站样式」（`keep_site_css=False`，只用内置排版），不勾等于保留。界面默认**不勾**，也就是默认保留原站样式——这一点和命令行的默认（丢弃）相反。想和命令行一致，就把这一项勾上。
- 一次最多提交 60 个 URL，多的会被静默丢掉。

## 我该用哪个模式

| 你的目的 | 模式 | 产物 | 代价 |
|---|---|---|---|
| 读文章、发给人、存进笔记 | `reader`（默认） | `.html`，只有正文 + 内置排版 | 丢掉原站样式、导航、评论 |
| 原样存档，以后要能看出原页面长什么样 | `full` | `.html`，整页结构 + 底部来源条 | 体积大（含广告/推荐流/侧栏） |
| 喂给脚本、入库、丢给 LLM | `data` | `.json` | 不产出可看的页面 |
| 批量存一堆链接 | 任意模式 + `-i` | 一堆文件 | 见[批量模式](命令行手册.md#批量模式) |

一句话：**要读用 reader，要存用 full，要处理用 data。**

## 一条龙：找链接 → 存一批 → 建书库

不想一个个复制 URL，可以先让 `discover` 替你找：

```bash
python webvault.py discover https://www.ruanyifeng.com/blog/ -n 10
```

它把一个列表页上的文章链接挑出来，按「像不像文章」打分排序打印。分数看的是 URL 形态和链接文字：路径里有日期或文章 slug、文字够长、同域——分就高；导航、登录、标签页、`.pdf` / `.jpg` 这类资源链接会被直接丢掉。

```
  1. [ 28.0] 科技爱好者周刊（第 415 期）：3D 版《看不见的城市
        https://www.ruanyifeng.com/blog/2026/10/weekly-issue-415.html
  2. [ 28.0] 科技爱好者周刊（第 414 期）：Jev 决策模型有什么用
        https://www.ruanyifeng.com/blog/2026/10/weekly-issue-414.html
```

可以直接一条龙存下来，也可以先导出清单、人工删掉不想要的：

```bash
# 发现 → 保存 → 建索引
python webvault.py discover https://www.ruanyifeng.com/blog/ --save -o D:\saves --workers 5
python webvault.py index D:\saves

# 或者：先导清单，挑完再存
python webvault.py discover https://site.com/blog --list urls.txt
python webvault.py -i urls.txt -o D:\saves
```

存多了以后，`index` 负责让你找得到：

```bash
python webvault.py index D:\saves
```

```
书库索引已生成
  扫描   D:\saves
  收录   57 项（128.4 MB）
  来源   8 个站点
  文件   D:\saves\index.html
```

生成的 `index.html` 双击就能开，可以搜索标题/网址/摘要、按来源站筛选、按时间/标题/体积排序。这个索引页自己也是零外部依赖的，和它索引的那些页面一样断网可用。

三个子命令的参数细节见[命令行手册](命令行手册.md#子命令indexdiscover-与-diff)。

> `discover` 不是爬虫框架：它不递归、不遵守 robots、不做任务队列持久化。它只负责「把这一页上的文章链接找出来」。

## 它什么时候偷偷改了

有些页面你并不需要存档，只需要知道它变没变：公告什么时候改的、价格什么时候调的、文档是不是悄悄更新了。这类问题「再存一次」回答不了——两个文件确实都在，但你不会想自己肉眼 diff 几千行 HTML。

`diff` 就是干这个的。前提是这个网址**已经成功保存过一次**（`reader` 或 `data` 模式）：

```bash
python webvault.py diff https://example.com/notice -o D:\saves
```

它会重新抓一次，把新正文和上次存的正文逐行比，只把改动的几行列出来：

```
内容有变化（对比 2026-10-17 09:54:11 那一版）：
  新增 2 行，删除 1 行（旧 3 行 → 新 4 行）

- 本周三(10 月 15 日)晚 22:00 开始系统维护,预计持续两小时。
+ 本周四(10 月 16 日)晚 23:00 开始系统维护,预计持续三小时。
+ 本次维护会同时升级数据库,维护后首次访问可能稍慢。
```

`- ` 是删掉的旧行，`+ ` 是新加的行，读法和 `git diff` 一样。没变的话就一句话：

```
没有变化。
  最近记录：2026-10-17 09:54:11（第 1 版）
```

这些历史不用你提前配置：每次用 `reader` 或 `data` 模式成功保存，正文都会顺手记进保存目录下的 `.webvault\`，`diff` 读的就是它。`full` 模式不参与——整页快照没有提取正文，没得比。

想看看都追踪了哪些页面，加 `--list`，它不抓取、只列清单：

```bash
python webvault.py diff --list -o D:\saves
```

```
已追踪 3 个页面（D:\saves）

  系统维护公告
     https://example.com/notice
     4 个版本 · 最近 2026-10-17 09:54:11
```

为什么比的是文字而不是 HTML：HTML 里塞满了每次抓取都不一样、内容其实没变的东西——时间戳、广告位、随机 id、CSRF token。拿 HTML 比，每次都会「有变化」，这个功能等于废掉。所以它只取提取出来的正文，按段落和句号切成行再比，改一个词只会显示那一行。

两个使用上的细节：

- `diff` 默认**不存新文件**，只把这次的结果记成新的比对基线。想顺便把有变化的那一版也存成 HTML，加 `--save`。
- 每个网址最多留 20 个历史版本，单版正文上限 2 MB。`?utm_source=` 这类跟踪参数会先被归一化掉，同一个页面不会因为来源不同变成两条记录。

完整参数和退出码见[命令行手册](命令行手册.md#webvault-diff和上次存的比看改了什么)。

## 常见问题

### 保存的文件多大？

看页面。纯文字文章（比如技术博客）通常在 **50 KB ~ 500 KB**，因为内置 CSS 只有几 KB，剩下的都是文字。图片多的页面会迅速涨到 **几 MB 到几十 MB**——图片经过 base64 后体积约膨胀 1/3。

默认总预算 `--max-total 24`（24 MB），单资源上限 `--max-asset 4`（4 MB）。**预算按 base64 之后的体积扣**（`_base64_size()`），所以 `--max-total` 就是产物体积的上限——不会出现「设了 24 MB 却得到 30 MB」的情况。想压小：

```bash
python webvault.py <url> -m full --max-total 8 --max-width 1200
```

如果你装了 Pillow，超过 24 KB 的大图会被压到 `--max-width` 以内并转成 JPEG（质量 82，取原图与压缩后较小的那个）；PNG 带透明通道的仍存 PNG。没装 Pillow 就只做「超预算就跳过」。

顺带一句：`--max-asset` 同时是**单个资源的读取上限**，所以超过它的资源不是被跳过，而是被读到上限为止然后照样内联——产物里会是一张不完整的图。**要排除超大图，目前不能指望 `--max-asset`**；要么把它设得足够大让图片完整，要么用 `--no-images`。

### 为什么有些图片没存下来？

按出现频率排序，通常是这几个原因：

1. **懒加载**。图片真实地址在 `data-src` / `data-original` / `data-lazy-src` / `data-echo` 里，脚本会优先读这些属性，但如果站点用的是 JS 动态拼地址（比如滚动时才计算），就抓不到。
2. **防盗链**。图床检查 `Referer`，返回 403。抓取时会带上目标页作为 `Referer`，但有些站点还会校验 Cookie 或签名，抓不到就是抓不到。
3. **超过单资源上限**。超过 `--max-asset`（默认 4 MB）的图会被读到上限为止——注意这里的行为是**截断后照样内联**，产物里会是一张不完整的图，而不是被跳过（原因见上一节）。真要排除它，把 `--max-asset` 调小只会让截断更早发生，所以更实际的做法是 `--no-images` 或者接受它。
4. **超过总预算**。预算扣完后剩下的资源全部跳过，进度里会有 `(budget)` 标记。
5. **`--local-only` 打开了**。非当前域的资源一律不抓。
6. **字体被 `--no-fonts` 排除了**。字体不内联，CSS 里的地址会被改写成绝对地址，所以图标字体仍需要联网。

跳过和失败的数量会在「资源」那一行里显示，命令行还会列出前 5 个跳过的 URL（前 100 个字符），方便你对症下药：

```
  跳过   3 个资源（前几个）：
         (budget) https://cdn.example.com/huge-hero.jpg
         https://img.example.com/hotlink-protected.png
```

### 会被反爬拦截吗？

会，而且这不是它能解决的问题。

抓取层用 `urllib`，默认带一个 Chrome 124 的 `User-Agent`、中文 `Accept-Language`、`Accept-Encoding: gzip, deflate`，支持自动解压、自己跟重定向（最多 8 跳）、失败重试 2 次（退避 0.4s / 0.8s）。**它不执行 JavaScript**，也不维护 Cookie 会话，没有代理设置，不能过 Cloudflare 之类的人机验证。

所以：

- 普通静态站、博客、新闻站——没问题。
- 强依赖 JS 渲染的 SPA——抓到的大概率是个空壳，正文提取会退回整页。
- 有验证码 / JS 挑战的站——拿到的是挑战页，或者 403。

抓取层对 4xx/5xx 不会直接放弃：**403/404 的响应体一样会读回来**再交给后续流程，因为有些站点的错误页反而有点信息量。所以只要服务器还给了页面，产物就照常生成，退出码是 `0`，但汇总块后面会多一段「存的是错误页」的警告（见下一条）。只有连响应体都没有时才算失败，退出码 `1`，错误信息在 stderr。

真要对付强反爬，正确做法是用你自己的爬虫（或浏览器）把 HTML 抓下来，再直接调 `src.pipeline.vault` 之外的下游函数——但注意 WebVault 的公开入口都是从 URL 开始的。

### 存下来发现是个 404 / 错误页怎么办？

说明服务器对这个网址返回了 4xx / 5xx。WebVault 会把错误页也存下来——那确实是服务器给出的页面，比什么都没有强——但产物不是你要的正文，所以汇总块后面会跟一段警告：

```
  ⚠ 服务器返回 HTTP 404，这个网址可能已经失效或无权访问。
    存下来的是服务器的错误页，不是你要的正文。
    如果这个网址本来就该失效，那没问题；否则请检查地址是否写错。
```

看到这段先回去核对地址：多打了一个字符、链接过期、或者页面只有登录后才可见，都会走到这里。**退出码仍然是 `0`**（保存动作本身成功了），所以脚本里批量跑的时候别只看退出码——批量模式的 `[OK]` 行会带 `⚠ HTTP 404` 这样的标记，程序化调用看 `VaultResult.http_status` / `http_warning`。

如果确认这个网址本来就该失效，留着这份错误页存档也无妨；不想留就把它从列表里删掉。

### 存下来只有几十个字，是不是工具坏了？

大概率不是坏了，是那一页的正文压根不在 HTML 里——现在很多站点用 JavaScript 在浏览器里现渲染内容，`urllib` 拿到的是一个空壳。

WebVault 会认出来并告诉你：

```
  ⚠ 这一页几乎提取不到正文（可能是需要 JavaScript 渲染的页面，或者这个网址实际跳到了一个错误页）。
    这类页面得用浏览器渲染才拿得到内容，WebVault 不执行 JavaScript。
    可以试试 -m full 留个原样快照，或者用浏览器手动另存。
```

两个判断依据：提取器置信度为 `0` 且退回了整页文本（说明整页找不到像正文的东西），或者正文不到 120 字而原始 HTML 超过 5000 字节。

判定是刻意保守的：像 `https://example.com` 那种只有一句话的页面不会报警，因为它的原始 HTML 本来就只有几百字节，属于「页面本身就短」，不是「内容没抓到」。

### 遇到 HTTPS 证书错误怎么办？

默认**不校验**证书，所以过期证书、自签名证书、证书链不全的站点都能正常抓——这正是默认行为的原因。代价是有中间人攻击风险。

需要严格校验时加 `--verify-tls`，页面抓取和内联资源会一起走严格模式。Python API 里等价的是 `vault(..., verify_tls=True)` 或 `fetch(..., insecure=False)`。

### 能存视频吗？

不能。`<video>` / `<audio>` 的媒体文件本身不会被内联，只处理 `poster` 封面图。`<iframe>` 在 reader 模式下会被当作垃圾清掉，在 full 模式下保留为外链标签（需要联网）。想要的是视频下载器的话，这个工具不是。

### 需要装 lxml 和 Pillow 吗？

不装完全能用。装了会有两点变化：

| 库 | 装了之后 |
|---|---|
| `lxml` | 解析走 `lxml.html` 快路径，大页面明显更快；失败自动退回纯标准库解析 |
| `Pillow` | 大图会被降采样 + 转 JPEG，`--max-width` / `--no-compress` 才有实际效果 |

没装 Pillow 时，`--max-width` 和 `--no-compress` **不产生任何效果**——图片原样内联。这一点容易被误认为 bug。

### 阅读模式为什么丢掉了原站样式？

因为站点 CSS 里的定位、栅格、广告位占位会把正文挤成一团。reader 模式默认套一层内置排版（44rem 正文宽、17px 字号、1.75 行高、`prefers-color-scheme` 暗色适配），只保留正文的语义结构。

**这个行为可以关掉**：加 `--keep-site-css`，reader 就会把原站样式拼在内置排版后面。做法是提取阶段先把 `<style>` 原文和外链样式表地址收集起来（`strip_junk(..., keep_styles=True)` 的返回值），渲染前再由 `pipeline` 把外链样式表抓回来重写，一起插进页面。

代价要清楚：原站规则排在内置排版之后，特异性又常常更高，所以它们会**直接压过** reader 的排版——「正文 + 原站样式」等于放弃「干净」这个卖点，而且样式表里的图片和字体也会被一起内联，产物明显变大。

想要最原汁原味的样子，仍然推荐 `-m full`——它不经过正文提取，整页结构和样式都保留。`--keep-site-css` 只在 reader 模式有意义。

> 补充：网页界面上的「干净排版（丢原站样式）」勾选框现在也会传到服务端（见[启动本地网页操作台](#启动本地网页操作台)），注意它的勾选状态是反的，而且界面默认不勾、也就是默认**保留**原站样式。

### 中文页面会不会乱码？

基本不会。编码检测顺序是：

```
显式声明 → BOM → HTTP 头 charset → <meta charset>（只看前 4 KB）→ 严格 UTF-8 试解 → gbk / big5 / shift_jis / euc-kr → utf-8
```

`gb2312` 会被规范化成 `gbk`，`utf8` → `utf-8`，`sjis` → `shift_jis` 等常见别名都做了映射。解码失败时还有一层兜底（utf-8 → gbk → latin-1 → 带 replace 的 utf-8），**任何情况下都不会因为编码抛异常**。Windows 控制台输出也做了 UTF-8 重配置，避免中文变乱码。

### 存下来的文件真的能离线打开吗？

reader 和 full 模式的目标是 **真·单文件**：CSS 内联成 `<style>`，图片/字体/CSS 里的 `url()` 全部转成 data URI，`@import` 递归展开（深度上限 4 层）。

但有两个诚实的例外：

1. **抓失败的资源会被改写成绝对 URL**，这些仍然需要联网。所以「是否完全离线」取决于有没有跳过项——看输出里「跳过 / 失败」这两个数是不是 0。
2. **`full` 模式默认保留 `<script>` 外链**（`--scripts keep`）。页面里的脚本仍指向原站，离线时加载不到。reader 模式没有这个问题，因为正文提取阶段就把 `<script>` 清掉了。

想强制干净：`--scripts drop`。

### 同名文件会被覆盖吗？

不会。输出前会检查目标路径，重名时依次尝试 `名字-1.html`、`名字-2.html`……最多到 999，之后拼时间戳。

批量模式下尤其要注意：**`-n/--name` 只在单个 URL 时有效**，批量时文件名一律由各页标题生成。
