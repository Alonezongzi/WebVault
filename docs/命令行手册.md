# WebVault 命令行手册

`python webvault.py` 的完整参考。适用于 WebVault v1.0.0。

```
usage: webvault [-h] [-o OUT] [-m {reader,full,data}] [-i INPUT] [-n NAME]
                [--stdout] [--workers WORKERS] [--timeout TIMEOUT]
                [--no-images] [--no-css] [--no-fonts]
                [--scripts {keep,inline,drop}] [--max-total MB]
                [--max-asset MB] [--no-compress] [--max-width MAX_WIDTH]
                [--local-only] [--keep-site-css] [--no-banner] [--verify-tls]
                [-q] [-V]
                [url [url ...]]
```

除了「给 URL 就保存」，还有三个子命令：

```
webvault index [-h] [-o OUT] [-t TITLE] [--no-recursive] [-q] [dir]
webvault discover [-h] [-n LIMIT] [--any-host] [--min-score MIN_SCORE]
                  [--min-text MIN_TEXT] [--timeout TIMEOUT] [--save]
                  [-o OUT] [-m {reader,full,data}] [--workers WORKERS]
                  [--list LISTFILE] [--json] [-q] url
webvault diff [-h] [-o OUT] [--context CONTEXT] [--max-lines MAX_LINES]
              [--list] [--timeout TIMEOUT] [--save] [--verify-tls] [-q]
              [url]
```

`index` 把保存目录变成可搜索的书库索引页，`discover` 从一个列表页里挑出文章链接（可以直接接着批量保存），`diff` 重新抓一次正文、和上次存的那一版比，看改了什么。详见[子命令](#子命令indexdiscover-与-diff)。

网址可以不带协议，脚本会自动补 `https://`（判断依据是「开头是不是 `scheme://`」）。`www.example.com/a/b` 和 `https://www.example.com/a/b` 都能用。

### 基本参数

## 几个容易搞错的参数

### `--max-total`：总预算，按 base64 之后的体积扣

内联过程中维护一个**共享的字节池**，初始值是 `--max-total × 1024 × 1024`。每内联一个资源就从池里扣掉它的开销，池子扣空之后剩下的资源全部跳过，统计里记 `(budget)`。

三个必须知道的行为：

1. **预算是全局共享的，不按类型分**。一张 3 MB 的封面图会吃掉 24 MB 里的 1/8，剩下的图片 CSS 字体共用剩余额度。
2. **扣的是内联之后的体积**。开销由 `_base64_size(n) = ((n + 2) // 3) * 4 + 48` 算出，也就是「base64 之后的长度 + data URI 前缀」，所以 `--max-total` 就是产物体积的上限，产物不会比它大三分之一。（早期版本按原始字节扣，才有那个「设 24 MB 却得到 30 MB」的问题。）唯一的例外是 `--scripts inline`：那条路按 `len(js)` 扣，是字符数不是字节数，非 ASCII 的脚本会少扣一点。
3. **图片先压缩、后扣费**。带 Pillow 时，`_process_image` 在扣预算之前执行，所以扣的是**压缩后**的大小——开压缩能明显省预算。但 CSS 和字体没有压缩环节，扣多少就是多少。

预算是**单向的**：扣掉就不会因为后面失败而归还（代码里有个 `_give_budget` 方法，但从未被调用）。

另外，预算耗尽不会报错，也不会让退出码变化——它只是「安静地少存点东西」。想知道到底跳了多少，看输出的「跳过」计数，或者看「资源」行末尾的 `预算 X/Y (Z%)`。

```bash
# 以 6 MB 预算存一个图片站，产物（含 base64 膨胀）不会超过这个数
python webvault.py https://example.com/gallery -m full --max-total 6
```

### `--max-asset`：单个资源的上限

默认 4 MB，够覆盖绝大多数网页大图。常见调整场景：

| 场景 | 建议 |
|---|---|
| 手机流量 / 想产物小 | `--max-asset 1` |
| 有高清摄影图，4 MB 不够 | `--max-asset 12 --max-total 60` |
| 只想要文字和图标 | `--no-images` |

这个值**同时是抓取时的下载上限**（`fetch(max_bytes=...)`），所以它既限制内联，也限制网络读取。

副作用必须说清楚：正因为两者是同一个数字，`_get()` 拿到的内容已经被 `resp.read(max_bytes)` 截断到上限了，`_inline_one()` 里那句「`len(data)` 超过上限就跳过」几乎永远不会命中。结果是**超过 `--max-asset` 的资源不是被跳过，而是被截断后照常内联**——产物里会出现一个不完整的图（浏览器里就是破图），`src` 也不会变成绝对地址。（只有测试里替换过 `_get()`、或者响应经 gzip 解压后膨胀时，超限分支才会真的走到。）

被跳过的资源（预算不足、抓取失败、外域）统计里算 `skipped`，URL 会进 `skipped_urls` 列表（最多 60 条），命令行打印前 5 条。

### `--scripts`：脚本怎么办

三个取值，行为差别很大：

| 取值 | `<script src="...">` | 内联的 `<script>...</script>` | 离线可用性 |
|---|---|---|---|
| `keep`（默认） | 原样保留，`src` 指向原站 | 原样保留 | ❌ 离线时脚本加载不到 |
| `inline` | 抓下来塞进标签内，删掉 `src` | 保留 | ⚠️ 能跑，但脚本可能依赖原站的全局变量 |
| `drop` | 删除 | 删除 | ✅ 最干净 |

`inline` 的实现细节：抓取失败的脚本会把 `src` 改写成绝对 URL 保留下来（不会丢标签）；超过 `--max-asset` 或没预算的同样退回绝对 URL；`.js` 按 UTF-8 解码（`errors="replace"`），非 UTF-8 的脚本可能乱码。**内联脚本不做任何改写**，等于把第三方 JS 原封不动塞进你的存档文件里——这是安全上的取舍，自己清楚就行。

默认给 `keep` 的理由是：full 模式的定位是「原样存档」，去掉脚本等于改变了页面行为。

而 **reader 模式实际上不需要关心这个参数**：正文提取阶段就会把 `<script>` 当垃圾清掉，所以不管你传什么，reader 产物里都不会有脚本。（`pipeline.vault` 里有一段「reader 模式默认 drop 脚本」的逻辑，但它只在调用方完全不传 `inline_options` 时才会生效；命令行总是会传一个 `InlineOptions`，所以走不到那个分支。）

推荐组合：

```bash
python webvault.py <url> -m full --scripts drop     # 干净的存档
python webvault.py <url> -m full --scripts inline   # 想要交互但离线
```

### `--local-only`：只抓同域资源

关掉「允许外部资源」后，只有**域名与当前页面完全相同**的资源会被抓取和内联，其余一律跳过。

对比的是 `urlsplit(url).hostname`，也就是**忽略端口和协议**——你的站是 `https://a.com`，资源在 `http://a.com/x.png` 仍然算同域；但 `img.a.com` 和 `a.com` 算**不同**域（没做子域匹配）。

什么时候用：

- 目标页面挂了大量第三方统计、广告、社交组件的图片，你只想要站内的东西。
- 你只想把**自己的**站点存下来，不想顺带把别人 CDN 拉一遍。
- 一个默认开启的外部资源白名单式限制（本质上 `--local-only` 更接近「黑名单掉外域」）。

被跳过的外域资源**不会被改写成绝对 URL 之外的处理**：`<img>` 的 `src` 保持原样（因为根本没进 job 列表），CSS 里的 `url()` 会保留原写法。也就是说这些引用仍然在文件里，只是没被内联，离线时表现为破图。

> 顺带一提：`src` 保持原样意味着它可能是相对路径。想让所有链接都变绝对地址，得靠内联成功。

### `--keep-site-css`：reader 里带上原站样式

默认 reader 只用 `render.py` 里那段内置排版（44rem 正文宽、17px 字号、1.75 行高、`prefers-color-scheme` 暗色适配），原站 CSS 一律丢掉。

加上 `--keep-site-css` 之后，`render_reader` 会把站点样式拼在内置 `READER_CSS` 之后（同一个 `<style>` 块里）。数据是这样凑齐的：

```
extract(..., keep_styles=True)   ← strip_junk() 把全文档的 <style> 原文和外链 <link> 地址
   │                               收集进 ExtractResult.styles，节点本身仍从树里摘掉
   ├─ 内联阶段                    ← 树里已经没有这些节点了
   └─ pipeline 补抓                ← collect_stylesheet_urls(ex, base_url) 取回外链地址，
                                    逐个 inliner._get() 抓取 + _rewrite_css() 重写，
                                    追加进 ex.styles["inline"]（样式表里的图片/字体也一起内联）
render_reader(keep_site_css=True) ← _extract_style_texts() 拼进模板，之后再看一眼树上
                                    还活着的 <style> 节点
```

几点要知道：

- 只在 **reader 模式**生效。full 模式本来就保留 `<style>` / `<link>`，data 模式不产出页面，两者都不看这个开关。
- 站点规则排在内置排版后面、选择器特异性又常常更高，所以它们会**直接压过** reader 的排版——「正文 + 原站样式」等于放弃「干净」这个卖点。
- 补抓那一步不看 `--no-css`：`--keep-site-css --no-css` 仍然会把外链样式表抓回来（连样式表里的图片一起内联）。
- 样式表抓不到时不会报错，只是那个文件里的规则缺失；抓取失败会在进度里显示一行「补抓样式表 …」。

早期版本的 `--keep-site-css` 是个空开关（样式在提取阶段就被删干净，渲染时收集不到任何东西），现在不是了。

### `--no-fonts`：不内联字体

字体没有独立的处理分支——它们是作为 CSS 里 `url(...)` 引用的资源被内联的，走 `_rewrite_css` → `_inline_one(kind="css-asset")` 这条路。`--no-fonts` 在 `_inline_one()` 里生效：

- `_is_font(mime, url)` 认字体：MIME 里含 `font`，或 URL 后缀是 `.woff` / `.woff2` / `.ttf` / `.otf` / `.eot`。
- 命中且 `fonts=False` 时**不内联**：资源计入「跳过」，`skipped_urls` 里留一条 `(font skipped) <url>`，CSS 里那个 `url()` 被改写成**绝对地址**（所以不会变成坏链，只是仍然需要联网）。
- 字体判定发生在扣预算之前，被跳过的字体不占 `--max-total` 的额度。

`woff` / `woff2` / `ttf` / `otf` 能被正确识别（靠魔数 `wOFF` / `wOF2` / `OTTO` / `\x00\x01\x00\x00`），MIME 类型正确。

`--max-asset` 仍然能拦住字体——不过是以「截断后内联」的方式，见上文 `--max-asset` 那一节。

早期版本的 `--no-fonts` 同样是个空开关（值被塞进 `InlineOptions.fonts` 后没人读），现在不是了。

### `--no-compress` 和 `--max-width`：没装 Pillow 就是空操作

图片压缩的完整条件链：

```
compress_images=True（默认）
  AND mime 不是 svg/gif/webp
  AND 原始大小 >= 24 KB
  AND Pillow 可用
```

任何一条不满足就原样内联。所以：

| 情况 | 结果 |
|---|---|
| 没装 Pillow | `--max-width` / `--no-compress` **完全不起作用** |
| 图片 < 24 KB | 不压缩（压了也不划算） |
| SVG / GIF / WebP | 不压缩（重新编码会破坏动画或矢量性） |
| 有透明通道的 PNG | 只在重采样之后取「更小的那个」，否则保留原图 |
| 其余 | 超过 `--max-width` 就按 LANCZOS 等比缩小，转 JPEG（quality 82、optimize、progressive），同样取更小的那个 |

JPEG 质量 82 是写死的，命令行没有暴露这个参数。要用别的质量，得从 `src.inline.InlineOptions(jpeg_quality=...)` 走 Python API。

### `-q / --quiet` 和 `--stdout` 的边界

`-q` 关掉的是：启动横幅、`· ` 开头的进度行、跳过的资源列表。**最终那个 `✔ 完成` 汇总块仍然会打印**——它不受 `verbose` 控制。

`--stdout` 会做三件事：不写文件（`write=False`）、不打印横幅和进度、把 HTML/JSON 直接写到标准输出。它是为管道设计的：

```bash
python webvault.py https://example.com -m data --stdout | jq '.title'
python webvault.py https://example.com --stdout > page.html
```

`--stdout` 只在「**恰好一个** URL」时可用。给了多个 URL 时会直接打印错误并以退出码 `2` 结束：

```
错误：--stdout 只支持单个 URL（批量时请去掉 --stdout）
```

所以它不会静默地把文件写到磁盘上，也不会把批量汇总混进管道。多个 URL 请用 `-o` 存盘。

### `-n / --name`：要自己带扩展名

```bash
python webvault.py https://example.com -n 存档.html    # ✔ 得到 存档.html
python webvault.py https://example.com -n 存档         # ✘ 得到无扩展名的文件「存档」
```

名字会被原样使用（`filename or 由标题生成`），**不会自动补 `.html` / `.json`**。另外它只在单个 URL 时有效；批量模式下所有文件名都由各自的页面标题生成，`-n` 会被忽略并在 stderr 打印一条提示。

### `--verify-tls`：严格校验 HTTPS 证书

默认**不校验**（`ssl.CERT_NONE` + `check_hostname=False`）。公开站点里过期证书、自签名证书、证书链不全的情况太常见，严格校验会让工具在正常网页上失败，所以默认行为是实用主义的选择，代价是有中间人攻击风险。

要严格校验就加 `--verify-tls`。这个开关会同时作用于**页面抓取和资源内联**（`fetch(insecure=...)` 与 `InlineOptions.verify_tls` 是同一条信息），所以不会出现「页面校验了、图片没有」这种半吊子状态。

Python API 的等价写法是 `vault(..., verify_tls=True)`，或者直接调 `fetch(url, insecure=False)`。

## 批量模式

给多个 URL，或者用 `-i` 指定列表文件，就会自动进入批量并发抓取（`ThreadPoolExecutor`，并发数 `--workers`）。

```bash
python webvault.py https://a.com https://b.com https://c.com
python webvault.py -i urls.txt -o D:\saves --workers 6
python webvault.py -i urls.txt https://extra.com -m full    # 两者会合并
```

位置参数和 `-i` 可以同时用，**位置参数在前**，文件里的追加在后面。合并后总数 > 1 就走批量。

输出形状：

```
批量保存 3 个 URL → D:\saves

  [OK] reader | 某篇文章标题 | 412.3 KB | 3200 字 | 内联 18
  [OK] reader | 另一篇 | 128.9 KB | 980 字 | 内联 4
  [FAIL] reader | 失败: HTTP 404 Not Found

完成：成功 2 / 失败 1，共 541.2 KB
失败的：
  https://b.com/gone  →  HTTP 404 Not Found
已保存到 D:\saves
```

每个 `[OK]` 行的格式是 `模式 | 标题（截断到 40 字）| 体积 | 正文字数 | 内联资源数`。`[FAIL]` 行是 `失败: 原因`。

**批量模式的注意点**（都是当前实现的真实行为）：

1. **`-n/--name` 无效**，文件名一律由标题生成，CLI 会打一条 stderr 提示。
2. **`--keep-site-css` 和 `--no-banner` 有效**：`vault_many()` 接收这两个参数并原样转发给每个 `vault()` 调用，所以批量时 reader 也能保留原站 CSS、full 也能关掉来源条。
3. **`--stdout` 被拒绝**：批量模式直接以退出码 `2` 退出并打印原因，不会静默写文件。
4. **单个 URL 失败不会中断整批**，失败项在最后统一列出。只要有一个失败，退出码就是 `1`。

`--workers`、`--timeout` 和所有 `--no-images` / `--max-total` 之类的内联参数在批量模式下同样生效（它们被打包成一个 `InlineOptions` 传给每个任务）。

抓取是并发的，但**写文件是各线程各写各的**，文件名冲突由 `unique_path` 加 `-1`/`-2` 后缀解决（这里有极小的 TOCTOU 窗口：两个线程同时检查到文件不存在，理论上会撞名。实际使用中概率很低）。

`--workers` 建议值：`4` 对一般站点合适；目标站有速率限制时降到 `1`~`2`；几十个 URL 的批量可以开到 `6`~`8`。开太大容易触发对方的频控，反而全是 403。

### URL 列表文件格式

纯文本，UTF-8（读的时候用 `errors="replace"`，所以 GBK 也能读进来，只是非 ASCII 可能变成替换字符）。

```text
# 以 # 开头的是注释，整行忽略
https://example.com/article/1

# 空行会被忽略

# 支持「标题 | URL」写法，方便自己看
阮一峰周刊第 286 期 | https://www.ruanyifeng.com/blog/2024/01/weekly-issue-286.html
某篇长文 | https://blog.example.com/2024/03/very-long-post
```

解析规则（逐行处理）：

| 输入 | 结果 |
|---|---|
| 空行 | 忽略 |
| 以 `#` 开头 | 忽略（只判断行首，前面有空格再跟 `#` 不算注释，会被当 URL 尝试） |
| 含 `\|` | 取**最后一个** `\|` 之后的部分，并 `strip()` |
| 其他 | 整行 `strip()` 后作为 URL |

也就是说 `标题 | URL` 里**标题只是给人看的，完全不参与后续流程**——不用于文件名，不用于日志，纯粹是注释。取「最后一个 `|`」意味着 `A | B | URL` 也能用，但 URL 本身含 `|` 的情况会被截断（URL 里带竖线极其罕见）。

行首行尾空白会被去掉，行尾的 `\r`（Windows 换行）也会被处理掉，所以直接拿记事本存的文件可以用。

## 子命令：index、discover 与 diff

命令行只在**第一个词**是 `index`、`discover` 或 `diff` 时才走子命令，否则位置参数照旧当作 URL 处理。所以 `webvault index` 不会去抓一个叫 "index" 的网站。

### `webvault index`：生成离线书库索引

扫描一个目录里的 WebVault 产物（`.html` / `.json`），生成同样零外部依赖的 `index.html`——双击打开就能搜索标题/网址/摘要、按类型筛选、按时间/标题/体积/来源站排序。

```bash
python webvault.py index                       # 扫描 ./vault，产出 ./vault/index.html
python webvault.py index D:\saves              # 扫描 D:\saves
python webvault.py index D:\saves -t 我的书库  # 换标题
python webvault.py index D:\saves -o D:\saves\index.html   # 指定输出文件
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `dir` | 要扫描的目录 | `./vault` |
| `-o, --out` | 输出位置：目录（索引写在里面）或具体的 `.html` 文件 | 扫描目录下的 `index.html` |
| `-t, --title` | 书库标题 | `WebVault 书库` |
| `--no-recursive` | 不递归子目录 | 关（默认递归） |
| `-q, --quiet` | 不打印汇总 | 关 |

输出形状：

```
书库索引已生成
  扫描   D:\saves
  收录   57 项（128.4 MB）
  来源   8 个站点
  文件   D:\saves\index.html
```

目录里一个产物都没有时，会多打一行提示。目录本身不存在时返回退出码 `2`。

索引页只收「自己的」产物：HTML 必须带 `wv-source` 或 `wv-captured` 这两个 meta（data 模式的 `.json` 除外），扫描目录根下的 `index.html` 会被跳过——索引页不把自己收进去。元信息只从文件前 200 KB 里读正则，不会把几十 MB 的产物整个解析一遍。

模式分类靠 `<meta name="wv-mode">`：reader / full 的模板各自写入 `content="reader"` / `content="full"`，data 模式的 `.json` 直接记作 `data`，所以索引页按模式筛选是准的。（早期版本两个 HTML 模板都不写这个 meta，产物一律被兜底标成 `reader`，按 `full` 筛选时筛不出东西；现在不是了。）

### `webvault discover`：找出这一页上的文章链接

给一个列表页（或任意页面），把「值得归档」的文章链接挑出来，按分数排序打印。它不递归、不遵守 robots、不做任务队列，就是「把这一页上的文章链接找出来」。

```bash
python webvault.py discover https://site.com/blog
python webvault.py discover https://site.com/blog -n 30 --min-score 5
python webvault.py discover https://site.com/blog --list urls.txt   # 先导清单，人工挑
python webvault.py discover https://site.com/blog --save -o D:\saves --workers 5
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `url` | 从这里发现链接 | — |
| `-n, --limit` | 最多返回多少条 | `50` |
| `--any-host` | 允许跨域链接 | 关（默认只留同域） |
| `--min-score` | 最低分数阈值 | `8` |
| `--min-text` | 链接文字最短长度 | `6` |
| `--timeout` | 抓这个页面的超时秒数 | `25.0` |
| `--save` | 发现后直接批量保存 | 关 |
| `-o, --out` | 保存目录（配合 `--save`） | `./vault` |
| `-m, --mode` | `--save` 时用的模式 | `reader` |
| `--workers` | `--save` 时的并发数 | `4` |
| `--list FILE` | 把发现的链接写进文件，便于之后用 `-i` 复用 | 空 |
| `--json` | 以 JSON 输出而不是列表 | 关 |
| `-q, --quiet` | 不打印进度 | 关 |

列表形状（`序号. [分数] 链接文字`，下一行缩进是 URL）：

```
  1. [ 28.0] 科技爱好者周刊（第 415 期）：3D 版《看不见的城市
        https://www.ruanyifeng.com/blog/2026/10/weekly-issue-415.html
  2. [ 28.0] 科技爱好者周刊（第 414 期）：Jev 决策模型有什么用
        https://www.ruanyifeng.com/blog/2026/10/weekly-issue-414.html
  3. [ 19.0] 更多文章……
        https://www.ruanyifeng.com/blog/archives.html
```

打分看的是 URL 形态和链接文字：路径 2 层最像文章（+6）、以 `.html` 结尾（+5）、有 slug / 数字 ID / 路径里有日期（各 +3）、文字够长（+4，超过 12 字再加 2，超过 120 字倒扣）、带标点或汉字（各 +1）、同域（+3）；`<main>` / `<article>` 里的链接再额外加 3 分。首页、登录/注册、标签/分类、搜索、关于、隐私，以及图片/CSS/字体/压缩包/文档/音视频这类资源链接会被直接丢掉，「首页 / 关于 / 更多 / 下一页」这类功能文字也一样。

几个行为细节：

- `--list` 写成 `链接文字 | URL` 的形式（文字里的 `|` 被替换成 `/`），首行是一句注释，所以可以直接喂给 `-i`。
- `--json` 输出的是 `{url, text, score, host, same_host}` 的数组，`score` 保留两位小数；列表行里的分数保留一位。
- `--save` 时每个 URL 的进度和 `[OK]/[FAIL]` 行都打到 **stderr**，最后一行是 `完成：成功 X / 失败 Y`；全部成功返回 `0`，有失败返回 `1`。`-m reader` 时脚本策略自动设为 `drop`。
- 一条都没发现（或页面抓不到）时返回退出码 `1`，并提示可以降低 `--min-score` 或加 `--any-host`。
- 库里的 `discover()` 默认 `limit=200`，CLI 的默认是 `50`——命令行更保守。

### `webvault diff`：和上次存的比，看改了什么

存下来的页面不会告诉你它什么时候变了。`diff` 回答的就是这个问题：重新抓一次，把新正文和**最近一版**逐行比，只把改动的行列出来。

```bash
python webvault.py diff https://example.com/notice -o D:\saves
python webvault.py diff https://example.com/notice -o D:\saves --context 1
python webvault.py diff --list -o D:\saves                 # 看都追踪了哪些页面
python webvault.py diff https://example.com/price --save    # 有变化时顺手存下新版本
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `url` | 要检查的网址（可选；不给就打印帮助并以 `2` 退出） | — |
| `-o, --out` | 保存目录，历史也从这里读 | `./vault` |
| `--context N` | 差异块之间保留的分隔：两个改动块相距超过 `2N+1` 行时，中间插一行 `  …` | `2` |
| `--max-lines N` | 最多输出多少行差异，超了截断并加一句提示 | `400` |
| `--list` | 列出所有已追踪的页面，不抓取 | 关 |
| `--timeout` | 抓这个页面的超时秒数 | `25.0` |
| `--save` | 有变化时顺便把新版本也存下来 | 关 |
| `--verify-tls` | 严格校验 HTTPS 证书 | 关 |
| `-q, --quiet` | 不打印「抓取 …」这类进度 | 关 |

有变化时：

```
$ python webvault.py diff https://example.com/notice -o D:\saves

内容有变化（对比 2026-10-17 09:54:11 那一版）：
  新增 2 行，删除 1 行（旧 3 行 → 新 4 行）

- 本周三(10 月 15 日)晚 22:00 开始系统维护,预计持续两小时。
+ 本周四(10 月 16 日)晚 23:00 开始系统维护,预计持续三小时。
+ 本次维护会同时升级数据库,维护后首次访问可能稍慢。
```

`- ` 是旧版里有、新版里没了的行，`+ ` 是新增的行，读法和 `git diff` 一致。没变化时只有两行：

```
没有变化。
  最近记录：2026-10-17 09:54:11（第 1 版）
```

`--list` 打印所有已追踪的页面，按最近记录时间倒序：

```
已追踪 3 个页面（D:\saves）

  系统维护公告
     https://example.com/notice
     4 个版本 · 最近 2026-10-17 09:54:11
```

**历史存在哪儿。** 每次用 `reader` 或 `data` 模式成功保存，正文都会被记一份到 `<保存目录>\.webvault\`：

```
D:\saves\
├── .webvault\
│   ├── history.json           # 每个 URL 的标题、最近时间、版本列表
│   └── text\
│       └── a1\
│           └── a1b2c3….txt    # 一个版本一份正文，按内容 sha1 命名
└── 系统维护公告.html
```

三条规则：

1. **只记正文，不记 HTML**。HTML 里的时间戳、广告位、随机 id、CSRF token 每次抓取都不一样，拿它比结果是「每次都有变化」，这个功能就没意义了。`diff` 比的是提取出来的正文，按块（段落、`h1`~`h6`、`<li>`、`<blockquote>`、`<pre>`、表格单元格等）切开，再按句号断句成行，改一个词只影响那一行。
2. **每个 URL 最多留 20 版**（`MAX_VERSIONS`），单版正文上限 2 MB（`MAX_TEXT_BYTES`）。更老的版本会从 `history.json` 的版本列表里滚掉；`text\` 目录下的旧文件不会跟着删，留着不影响比对。
3. **URL 先归一化再当键**。`?utm_source=` / `?fbclid=` 这类跟踪参数在算键时就被丢掉，所以同一个页面从不同渠道进来只算一条记录，不会每次都是「新页面」。

`full` 模式不记录：它没有提取正文，没有可比的文本。`.webvault\` 是点开头的隐藏目录，`index` 扫描时会跳过它（`library.scan()` 不进入点开头的目录），所以它不会变成书库条目。

**比对不等于保存。** `diff` 默认不写产物文件，只更新比对基线——下次比的基准就是这一次。想让有变化的那一版也落成 HTML，加 `--save`。第一次检查某个网址时没有可比的对象，会打印「这是第一次检查这个页面，已记录为基线。」，并以 `0` 退出。

退出码：抓取失败、抓到 Cloudflare / 登录墙这类拦截页（会明说「比对结果没有意义」）、或者没提取到正文时返回 `1`；没给网址时打印帮助并返回 `2`。有变化、没变化、第一次记录都是 `0`——想让脚本按「变没变」分支，看输出里的 `内容有变化` / `没有变化。`，别指望退出码。

## data 模式的 JSON 结构

`-m data` 产出的是 JSON。写到文件时是 `indent=2` + `ensure_ascii=False`（中文不会变成 `\uXXXX`）；`--stdout` 时同样是 `indent=2`。

### 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `url` | string | 抓取用的地址——**实际是重定向后的最终地址** |
| `final_url` | string | 同上。当前实现里和 `url` 是同一个值，冗余字段，为将来区分保留 |
| `requested_url` | string | 你**原始输入**的 URL（由 `pipeline` 追加）。想记录「我请求了哪个地址」用这个 |
| `captured` | string | 抓取时间，本地时区，`YYYY-MM-DD HH:MM:SS` |
| `generator` | string | 固定 `"WebVault"` |
| `title` | string | 标题。优先级 `og:title` → `twitter:title` → `<title>` → 第一个 `<h1>` |
| `byline` | string | 作者。取自 meta、`rel=author` 链接、或 `byline`/`author-name`/`作者` 一类 class。取不到是 `""` |
| `excerpt` | string | 摘要。`og:description` → `description` → `twitter:description` |
| `site_name` | string | `og:site_name`，没有则用域名（会剥掉 `www.`） |
| `lang` | string | `<html lang>` 的第一段（`en-US` → `en`）；没有 `lang` 属性时**默认为 `"zh"`** |
| `text` | string | 正文纯文本，已做 Unicode NFKC 归一化、去零宽字符、压空白、压空行 |
| `html` | string | 正文 HTML 片段（**不是**完整文档）。是内联后的活 DOM 序列化结果 |
| `word_count` | int | 加权字数，见下文 |
| `confidence` | float | 提取置信度，0~1，保留 3 位小数 |
| `method` | string | `"readability"` 或 `"fallback"` |
| `images` | array | 图片列表，见下 |
| `links` | array | 链接列表，见下 |
| `tables` | array | 表格，二维字符串数组的数组 |
| `headings` | array | 标题大纲，见下 |
| `inline_stats` | object | `{fetched, inlined, skipped, failed}`，由 `pipeline` 追加 |

### `word_count` 不是一个字符数

计算方式是**中文加权的长度**，不是 `len(text)`：

```python
word_count = int(汉字数 * 1.6 + 其他字符数 * 0.6)
```

汉字（`\u4e00-\u9fff` 和 `\u3400-\u4dbf`）按 1.6 计，其他字符（含英文、数字、标点、空白）按 0.6 计。设计意图是让中英文页面的字数"可比较"——一段 100 个汉字的中文和一段 270 个字符的英文给出的数差不多。

**所以 `word_count` 既不是字数也不是字符数**，别拿它当精确指标用。需要准确字符数请直接 `len(data["text"])`。

### `confidence` 怎么来的

```
confidence = min(1.0, (最佳候选得分 / 400) * 0.6 + (最佳候选文本量 / 页面总文本量) * 0.4)
```

走 fallback 时（提取失败，退回整个 `<body>`）会被压到**最多 0.25**。

经验值：0.6 以上通常是干净的正文页；0.3 上下多半是提取勉强成功、正文里混了别的东西；接近 0.25 说明基本就是整页回退了。

### `method`

| 值 | 含义 |
|---|---|
| `readability` | 打分选出了正文容器，正常路径 |
| `fallback` | 没选出容器（无候选、最高分为负、或选中容器文本量 < 60），退回 `<body>` 或整棵树 |

只有这两种。`ExtractResult` 里还有 `method="error"` 和 `method="full"` 两种取值，但前者会被 `pipeline` 立即改写成 `fallback`，后者只用于 full 模式（不产出 JSON），所以 JSON 里看不到。

### `images[]`

```json
{ "src": "data:image/png;base64,iVBORw0KG...", "alt": "示意图", "title": "", "width": "", "height": "", "inline": true }
```

| 键 | 说明 |
|---|---|
| `src` | 图片地址。**内联成功后是 data URI**，`--no-images` 或内联失败时是原始值（可能是相对路径） |
| `alt` / `title` | 原属性，没有就是 `""` |
| `width` / `height` | **HTML 属性的字符串值**，不是真实像素尺寸；没写属性就是 `""` |
| `inline` | `src.startswith("data:")` 的结果。判断是否已内联就看这个 |

想拿到**原始 URL** 而不是 data URI，加 `--no-images`：内联阶段不会碰 `<img>`，`src` 保持页面里的原值（可能是相对路径，需要你自己用 `requested_url` 做 base 去拼）。这也顺便让运行快很多、JSON 小很多。

```bash
# 爬虫流程的推荐用法：只提取，不下载任何资源
python webvault.py https://example.com/article -m data --no-images --no-css -o ./out
```

### `links[]`

```json
{ "href": "https://example.com/tag/python", "text": "Python", "rel": "" }
```

| 键 | 说明 |
|---|---|
| `href` | 原样保留，**不做相对路径转绝对**（正文阶段的 `urljoin` 只用于资源抓取，不改属性） |
| `text` | 链接文本，空白已压缩，**截断到 200 字符** |
| `rel` | 原 `rel` 属性 |

两条过滤规则：`href` 为空、或 `href` 以 `javascript:` 开头的会被丢掉；`(href, text)` 完全相同的重复项只保留第一条。

注意 `#` 锚点和 `mailto:` **不在过滤范围内**，会被保留。

### `tables[]`

每张表是一个二维数组，行是 `<tr>`，单元格是 `<td>` / `<th>` 的文本（空白已压缩）。空行（一个 cell 都没有的）会被跳过。

```json
"tables": [
  [
    ["语言", "份额"],
    ["Python", "28.5%"],
    ["JavaScript", "22.1%"]
  ]
]
```

**不保留表头语义**——`<th>` 和 `<td>` 混在同一个数组里，分不出哪行是表头。合并单元格（`rowspan` / `colspan`）也不会展开，只是按出现顺序平铺。要精确的表格结构请自己解析顶层 `html` 字段。

### `headings[]`

```json
[ { "level": 1, "text": "文章标题" }, { "level": 2, "text": "第一节" } ]
```

`level` 是 1~6（`h1`~`h6`），按文档顺序排列，直接可以当大纲用。空标题会跳过。

### 完整示例

```json
{
  "url": "https://example.com/final",
  "final_url": "https://example.com/final",
  "requested_url": "https://example.com",
  "captured": "2026-10-17 00:46:39",
  "generator": "WebVault",
  "title": "示例文章",
  "byline": "张三",
  "excerpt": "这是一篇示例文章的摘要。",
  "site_name": "示例站点",
  "lang": "zh",
  "text": "正文第一段……",
  "html": "<div class=\"content\"><p>正文第一段……</p></div>",
  "word_count": 1832,
  "confidence": 0.812,
  "method": "readability",
  "images": [
    { "src": "data:image/jpeg;base64,/9j/4AAQ...", "alt": "配图", "title": "",
      "width": "800", "height": "", "inline": true }
  ],
  "links": [
    { "href": "/tag/python", "text": "Python", "rel": "tag" }
  ],
  "tables": [],
  "headings": [
    { "level": 1, "text": "示例文章" },
```

## 输出解读

单个 URL 成功时的汇总块：

```
✔ 完成
  标题   Example Domain
  模式   reader
  大小   4.1 KB
  正文   93 字，0 图
  资源   抓取 0 / 内联 0 / 跳过 0 / 失败 0；原始 0 B → 内联 0 B；预算 0 B/24.0 MB (0%)
  耗时   1.2s
  文件   C:\...\vault\Example-Domain.html
```

| 行 | 说明 |
|---|---|
| 标题 | 提取到的标题，取不到显示 `(无)` |
| 模式 | `reader` / `full` / `data` |
| 大小 | **产物字节数**（UTF-8 编码后）。data 模式是 JSON 字符串的长度 |
| 正文 | 加权字数（同上文 `word_count`）和图片数。**只在 reader / data 模式出现** |
| 资源 | `抓取 N` 是发起的资源请求数，`内联 N` 是成功的，`跳过 N` 含超预算/外域/字体跳过，`失败 N` 是抓取出错。`原始 X → 内联 Y` 里 `Y` 是 data URI 的文本长度（约 1.33 倍膨胀）。末尾的 `预算 X/Y (Z%)` 是实际扣掉的额度 / `--max-total`，`X` 按 base64 之后的体积算 |
| 耗时 | 从开始到最后的总秒数，保留 1 位小数 |
| 文件 | 实际写入路径（含自动加的 `-1` 后缀） |

失败时：

```
✘ 失败：HTTP 403 Forbidden
  HTTP 403
```

第一行是 `error`，第二行只在拿到了 HTTP 状态码时出现（会打到 stderr）。

> 注意「资源」行的 `抓取 0 / 内联 0` 在 `--no-images` 之类的场景下是正常的——没发请求自然都是 0。

### 服务器返回 4xx/5xx 时

页面照样会存下来——服务器确实返回了这一页，存它比什么都不存要好。但存的是错误页，不是你要的正文。所以汇总块后面会多一段警告：

```
✔ 完成
  标题   404 Not Found
  模式   reader
  ...

  ⚠ 服务器返回 HTTP 404，这个网址可能已经失效或无权访问。
    存下来的是服务器的错误页，不是你要的正文。
    如果这个网址本来就该失效，那没问题；否则请检查地址是否写错。
```

退出码**仍然是 `0`**，因为保存动作本身成功了。程序化调用看两个字段：`VaultResult.http_status`（上游状态码，非 0 就说明服务器返回了错误）和 `VaultResult.http_warning`（可直接展示的文案），`summary()` 里也会带一段 `⚠ HTTP 404`。批量模式的 `[OK]` 行同样带着这个标记：

```
  [OK] reader | 404 Not Found | 4.1 KB | 93 字 | 内联 0
```

早期版本把 404 报成平平无奇的 `✔ 完成`，看起来和正常保存一模一样——这是修掉的一个坑。

### 正文提取不到东西时

另一类"看着成功、其实是空壳"的情况：页面本身能打开，但正文全靠 JavaScript 渲染。`urllib` 拿到的 HTML 里根本没有内容，提取器只能退回整页文字，字数量少得可疑。

满足下面任一条件就会标 `thin_content`：

- 提取器的置信度是 `0`，且走了 `fallback`（说明它在整页里找不到任何像正文的东西）
- 正文不足 120 字，而原始 HTML 超过 5000 字节

```
  ⚠ 这一页几乎提取不到正文（可能是需要 JavaScript 渲染的页面，或者这个网址实际跳到了一个错误页）。
    这类页面得用浏览器渲染才拿得到内容，WebVault 不执行 JavaScript。
    可以试试 -m full 留个原样快照，或者用浏览器手动另存。
```

`summary()` 里带 `⚠ 正文过少`，`VaultResult.thin_content` / `thin_advice` 可程序化读取。`full` 模式不做正文提取，不会报这个。

判定刻意保守：`https://example.com` 只有 93 字，但它的原始 HTML 才 577 字节，属于"本身就很短"，不报警。误报比漏报更烦人。

## 退出码

| 码 | 何时出现 |
|---|---|
| `0` | 成功。批量模式下表示**全部成功**。`diff` 的「有变化 / 没变化 / 第一次记录基线」都是 `0` |
| `1` | 失败。包括：没给任何 URL（打印横幅 + 帮助）、抓取失败、服务器返回空内容、解析失败、写文件失败、批量中有任意一项失败、`--stdout` 模式下抓取失败、`discover` 抓不到页面或没发现任何链接、`diff` 抓取失败 / 抓到拦截页 / 没提取到正文 |
| `2` | `-i` 指定的 URL 列表文件**不存在**；`index` 的扫描目录不存在；批量模式下给了 `--stdout`；`diff` 没给网址（打印帮助） |
| `130` | 用户按 `Ctrl+C` 中断（`KeyboardInterrupt`，打印「已中断」到 stderr） |

两点补充：

- **`2` 会和 argparse 冲突**。参数写得不对（比如 `-m` 给了不存在的模式）时 argparse 自己会 `exit(2)`，所以看到 2 要先区分是「WebVault 自己返回的」还是「参数写错了」。前者有中文提示（「错误：找不到 URL 列表文件 …」「错误：目录不存在 …」「错误：--stdout 只支持单个 URL…」），后者是 argparse 的英文 `usage:` 输出。
- **批量模式不会因为单项失败而提前退出**，它总是跑完所有 URL 再汇总，最后按「有没有失败项」决定返回 0 还是 1。

脚本里用：

```bash
python webvault.py -i urls.txt -o ./saves -q
if [ $? -ne 0 ]; then
  echo "有页面没存下来，检查上面的失败列表"
fi
```
